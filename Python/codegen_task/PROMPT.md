Paraphrased from the conversation that produced `Python/codegen_task`, so

> Clone https://github.com/google-research/codegen-classroom next to the

> - Minimal or zero changes to the codegen-classroom library; keep all task

> - Students may use any library (TensorFlow, JAX, PyTorch), but the artifact
>   must be a TFLite model the firmware can run.
> - Custom scoring inside the task: accuracy plus on-device cost such as
>   latency, FLOPs, model size, arena, parameter count, int8 coverage, and
>   robustness metrics such as worst-class recall and Null false-trigger rate.
>   Include as many useful metrics and tips for the students as possible.
> - Include `gemini-4-argon` among the students.
> - Set it up to demonstrate hill climbing across runs and to rerun
>   automatically when new recordings arrive.
> - Prompt the human for more recordings when data is thin.
> - Keep a `PROMPT.md` summarizing the prompts so the task is reproducible.

Design decisions that followed from this request:

- Students attach the TFLite bytes to `y_pred_df.attrs["tflite_model"]`; a
  custom validator analyses the artifact in the parent thread and hands cost
  metrics to the scorer through a thread-local, so the library stays unmodified.
- The validator reruns the TFLite model on raw `X_val` and requires agreement
  with the returned predictions, which forces normalization into the graph.
- Splits are frozen per class by a hash of the file name, so the test set is
  stable as recordings accumulate; `solutions/best_solution.md` seeds the next
  run; `watch.py` reruns on dataset change; `--deploy` promotes to
  `Arduino/Codegen/model_data.h` only when the test score improves.
- A dedicated `Arduino/Codegen` sketch registers exactly the allowed ops,
  handles int8 or float I/O, and offers a `REPLAY` mode for on-device
  evaluation, leaving the upstream `Inference` sketch untouched.

## System instruction (rendered)

# Task: XIAO nRF52840 Gesture Classifier (TFLite Micro)

## 1. Objective

Classify 1 second accelerometer windows from a Seeed XIAO nRF52840 Sense (LSM6DS3, 100 Hz, raw g units) into 9 classes: `Flick`, `Null`, `Pendulum`, `Poke`, `Punch`, `Roll`, `Shake`, `Slap`, `Twirl`. The winning model is flashed to the board and runs under TensorFlow Lite Micro on a 64 MHz ARM Cortex-M4F with 1 MB flash shared with the application and 256 KB RAM, using portable scalar C++ reference kernels rather than ARM CMSIS-NN SIMD intrinsics (so every MAC operation directly costs CPU cycles). On the device the model runs continuously on a sliding window, so avoiding false triggers on everyday motion matters as much as recognizing gestures across shifted window timing and grip variation.

Overall score is a weighted sum of normalized metrics in three groups:

- **Prediction quality (0.68):** macro F1 (0.42), balanced accuracy (0.09), worst-class recall (0.11), Null false-trigger rate (0.06, lower is better).
- **On-device cost (0.22, scored 1.0 at zero and 0.0 at soft budget):** TFLite size KB (0.08, budget 16), MFLOPs (0.05, budget 0.2), activation arena KB (0.03, budget 6), host latency ms (0.02, budget 0.05), estimated Cortex-M4F latency ms (0.02, budget 18), parameters in thousands (0.02, budget 6).
- **Deploy hygiene (0.10):** int8 op fraction (0.05), prediction-to-TFLite agreement (0.03), training wall-clock time (0.02).

Metrics summary:
-   **arena_kb:** Estimated peak activation memory in KB (budget 6), Lower is better (Weight: 0.03)
-   **balanced_accuracy:** Balanced Accuracy, Higher is better (Weight: 0.09)
-   **exec_time:** Time taken to execute generated code., Lower is better (Weight: 0.02)
-   **f1_macro:** F1 Score (Macro), Higher is better (Weight: 0.42)
-   **host_latency_ms:** Host TFLite latency per inference in ms (budget 0.05), Lower is better (Weight: 0.02)
-   **int8_fraction:** Fraction of dense/conv ops running on int8 activations, Higher is better (Weight: 0.05)
-   **mcu_ms_est:** Estimated Cortex-M4F latency in ms (from MACs) (budget 18), Lower is better (Weight: 0.02)
-   **mflops:** Estimated MFLOPs per inference (budget 0.2), Lower is better (Weight: 0.05)
-   **model_kb:** TFLite flatbuffer size in KB (budget 16), Lower is better (Weight: 0.08)
-   **null_fpr:** False trigger rate: Null windows classified as a gesture, Lower is better (Weight: 0.06)
-   **params_k:** Weight parameters in thousands (budget 6), Lower is better (Weight: 0.02)
-   **tflite_agreement:** Agreement between returned predictions and the TFLite model run on raw X_val (quantization drift), Higher is better (Weight: 0.03)
-   **worst_class_recall:** Recall of the worst class, Higher is better (Weight: 0.11)

## 2. Data Contract

- **Inputs:**
  * `X_train` (pd.DataFrame, 96 rows): 300 float columns `s000_x, s000_y, s000_z, ..., s099_z` holding one 100x3 window in row-major time order, plus string column `recording_id`.
  * `y_train` (pd.DataFrame): single integer column `'label'` with class indices 0..8 in the order `Flick`, `Null`, `Pendulum`, `Poke`, `Punch`, `Roll`, `Shake`, `Slap`, `Twirl`.
  * `X_val` (pd.DataFrame, 37 rows): same columns as `X_train`.
- Use `recording_id` as the group key for any internal cross-validation and drop it before modelling.
- Values are raw accelerometer readings in g (`+X` toward USB-C cable edge, `+Y` toward left pin edge, `+Z` up out of the chip face). Gravity (`~1.0 g` at rest) is present and encodes board pose across stationary and hand-held rest (`Null`), palm and finger strikes (`Slap`, `Poke`), cable motions (`Flick`, `Twirl`, `Pendulum`), and direct wrist motions (`Shake`, `Punch`, `Roll`).
- **Output:** return `(y_pred_df, feedback)`:
  * `y_pred_df` (pd.DataFrame): index identical to `X_val.index`, one integer column `'label'` with the predicted class index for every row, and `y_pred_df.attrs['tflite_model']` set to the `bytes` returned by `tf.lite.TFLiteConverter(...).convert()`.
  * `feedback` (str): 4 to 8 concise lines logging the hypothesis, validation macro F1 and worst-class recall, TFLite KB, parameters, MFLOPs, int8 fraction, agreement, and runtime.

## 3. Evaluation

- **Validation protocol:** The evaluator calls `solution()` 3 times per cycle, once per stratified fold over all learning recordings, and scores the concatenated out-of-fold predictions. Each call sees a different `X_train`/`X_val` pair, so do not run your own K-fold inside `solution()`; a cheap internal hold-out for early stopping is fine. The held-out evaluation splits test continuous sliding-window conditions including shifted timing, slight wrist tilt, amplitude variation, and boundary Null handling.
- **Deploy contract (hard, checked every cycle):** the attached TFLite model must (a) accept 300 values as a single fixed-shape input tensor with batch 1; (b) produce 9 class scores; (c) use only firmware-supported ops: `ABS`, `ADD`, `ARG_MAX`, `AVERAGE_POOL_2D`, `CAST`, `CONCATENATION`, `CONV_2D`, `DEPTHWISE_CONV_2D`, `DEQUANTIZE`, `EXPAND_DIMS`, `FULLY_CONNECTED`, `GATHER`, `HARD_SWISH`, `L2_NORMALIZATION`, `LEAKY_RELU`, `LOGISTIC`, `MAXIMUM`, `MAX_POOL_2D`, `MEAN`, `MINIMUM`, `MUL`, `PACK`, `PAD`, `QUANTIZE`, `REDUCE_MAX`, `RELU`, `RELU6`, `RESHAPE`, `SHAPE`, `SLICE`, `SOFTMAX`, `SPLIT`, `SQRT`, `SQUARE`, `SQUEEZE`, `STRIDED_SLICE`, `SUB`, `TANH`, `TRANSPOSE`, `UNPACK`; (d) be at most 64 KB with an estimated activation arena at most 40 KB; (e) match `y_pred_df` on at least 95% of rows when the evaluator runs your TFLite bytes directly on raw `X_val`. Any normalization or feature transformation must therefore live inside the exported graph.
- **Per-call wall-clock budget:** 150 s per call of `solution()`. Because of the 3 folds, keep a single call well under the budget. **Final evaluation budget:** 480 s on 133 learning rows.
- **Resources:** CPU only, no GPU, no network.

## 5. Principles

- **In-graph preprocessing with minimal op overhead:** Learn normalization statistics on the training split and bake them into the first layer (`tk.norm_layer(x_tr)`). Keep early tensor shapes and derived operations lean, since every extra operator node adds flatbuffer metadata and early channel expansion increases peak activation arena.
- **Temporal structure and amplitude summary:** Gestures differ in both peak impact magnitude and temporal ordering across the 1 second window. Choose temporal feature extractors and pooling layers that preserve both amplitude extremes and coarse temporal progression while keeping the classifier head small.
- **Full-integer quantization:** Converting weights and activations to int8 (`tk.to_int8_tflite`) shrinks model size roughly 4x and maximizes `int8_fraction`. Calibrate with representative windows covering both low-energy rest and high-g impacts.
- **Data-centric generalization at zero on-device cost:** With only a few recordings per class, training-time augmentation (`tk.augment`), realistic background negatives (`tk.hard_negatives`), and class weighting (`tk.class_weights`) improve sliding-window generalization without adding a single byte or MAC to the exported TFLite flatbuffer.

## 6. Pitfalls

- Returning predictions from the float Keras model instead of running the converted TFLite bytes (`tk.predict_tflite`) fails the agreement check.
- Training multiple models, ensembles, or teacher-student distillation pipelines inside `solution()` wastes the per-call CPU budget; train a single compact model per call.
- Running `tk.grouped_oof` inside `solution()` when `cv_folds > 1` multiplies runtime across folds; train once on `X_train` and predict `X_val` directly.
- Using ops outside `ALLOWED_OPS` (such as `SUM` from `tf.reduce_sum` or `SQUARED_DIFFERENCE` from `tf.math.reduce_variance`) fails the deploy validator; stick to `MEAN`, basic arithmetic, convolutions, pooling, and dense layers.
- TensorFlow CPU `DepthwiseConv2D` requires equal row and column strides; use symmetric strides on 4D tensors or stride with standard convolution and pooling layers.
- `tk.augment` already includes the original training windows alongside the augmented copies, and `SparseCategoricalCrossentropy` does not support `label_smoothing` (use one-hot labels with `CategoricalCrossentropy` if smoothing).
- Dynamic `None` dimensions beyond batch 1, non-integer predictions, or index mismatches with `X_val.index` fail validation immediately.

## 7. Iteration Discipline

- **Cycle 0:** start from a simple working baseline that satisfies the deploy contract end to end.
- **One lever per cycle:** change one aspect at a time—in-graph normalization, quantization, architecture family, temporal pooling, data augmentation, or regularization—and keep changes that improve validation score or cut footprint at equal accuracy.
- **Read the score breakdown:** target whichever component (F1, worst-class recall, Null false-trigger rate, or KB/MFLOPs/arena) is currently dragging down `overall_score`.
- **Use `feedback` as a concise lab log:** record your hypothesis, validation metrics, model size, MFLOPs, int8 fraction, and runtime every cycle.
